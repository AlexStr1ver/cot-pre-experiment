## 必须带入下一阶段的三个解释限制

**1. 归一化下降不等于原始熵下降。** 第8题在2055/4173处，ASAG原始熵相对1k分别上升6.330%/10.765%，除以ln(keys)后才得到−2.149%/−6.510%。它表示熵增长慢于长度归一化项，仍可能有信息，但需要控制长度。第8题2055处raw-tail32归一化H反而上升6.153%，不能把两个窗口混用或挑选更合意的方向。

**2. 内容置信度要连同覆盖率看。** 正确的`-1`被分成`['{-','1','}\n']`。严格内容C排除了混合token`{-`，所以约.99955/.99699只覆盖数字1，即答案字符的50%，不包含负号。主C没有漏掉该token；这是解释诊断列时的限制，并非主C计算错误。

本次已从保存的token概率离线补算“与答案内容有交集的整个token的概率均值”：两个正确点分别为 **.993181/.982494**，不需要再跑GPU。这列包含`{-`中的格式概率，不能冒充纯内容或正确性概率，也不替换原主指标。第8题从2055到4173的主C下降中，约 **91.6%** 来自闭合token概率下降。

**3. FP32阈值不能直接迁移BF16。** 在唯一可跨轮比较的case1/cut4103，FP32相对旧BF16的H变化为raw-tail32 **−1.756%**、ASAG窗口 **−1.970%**。这个尺度与本轮部分位置间变化相近；它不否定同精度内测量，但要求跨精度分别校准。旧native前缀来自BF16，本次在固定离散前缀上用FP32诊断；尚未证明在线FP32轨迹会经过相同位置。

## 是否有测试遗漏

没有发现预定九点漏跑。以下是覆盖边界，优先级不同：

- **下一轮顺带补：** 双chunk真实模型检查只在case1/4103做过；实际最长输入是case6/4203的4358token。补case6/4203、case8/4173两点，覆盖另外两题的长前缀。预算允许时可加case8/2055这个早期正确点；无须先重跑全部旧实验。
- **下一轮记录：** 当前只有权重文件大小，没有完整safetensors内容SHA。补本地权重指纹便于跨轮身份核对；仍需可信发布记录才能映射到论文cold-start/T/T+E行。
- **目前没验证：** 真模型长序列full reference、独立进程重复、BF16/高效后端桥接。双chunk与CPU full-reference测试不能完全排除共同实现偏差；不建议为此默认保存所有层4k attention而增加显存风险。
- **实质研究问题尚未测：** 摘要动作净收益、联合信号相对单信号增益、未见题泛化、含监测与重建开销的在线总成本。这些应在下一阶段设计中验证，不是本轮单元测试失效。

## 下一步方向与执行顺序

保持原始免训练方向；先不部署控制器，不用这九点调复杂规则，不转为训练探针。

1. **补上述两点数值检查与权重指纹。** 继续FP32，不混合精度阈值；负号诊断已经离线补齐。
2. **开发并自测新的公平预算分支运行器。** 旧A/B代码不能直接复用：A会在首段length限制处提前停止，B强制摘要会额外占掉一个segment。新协议以共同剩余预算`16384-cut`为准，摘要、失败尝试都计费，明确失败回退与统计口径。
3. **先运行一个预定A/B对，再完成同九点的18条轨迹、seed2026。** A继续原生推理；B立即生成摘要、重置后继续；C使用本轮已有短答案作为答案就绪对照。只按执行/预算是否正常决定是否继续，不根据首对答对与否挑点。
4. **第一批工程通过后，全部九点补两个seed。** 共54条A/B；不能只给“赢家”追加种子。再依据动作差异决定是否扩展开发题和简单规则对照。test120继续封存。

首批18条的最坏追加生成上限 **251,092 token**，不能拿本次13秒信号采集耗时估计分支实验时长。应先测首个A/B对的实际吞吐，再安排算力。下一阶段代码尚未实现，本文没有把协议建议写成已完成实验。

最关键的新证据是：**B在什么状态下比A更好，而这些状态是否能由H+C在动作前辨认？** 若只观察到“高C能早答”，贡献更接近ASAG已有范围；要支持摘要／重置方向，需独立证明该动作的条件性净收益。现在值得继续这一轮最小动作实验，尚无顶会级贡献已成立的证据。
