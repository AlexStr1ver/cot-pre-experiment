# 下一步最小协议：先补关键测量检查，再验证动作收益

日期：2026-10-24（北京时间）。这是基于阶段 2.1 返回结果制定的**下一轮协议建议，尚未实现或执行新的 GPU 分支实验**。保留免训练 attention 熵变化＋短答案置信度选择摘要／重置时机的原方向；不训练探针，不覆盖旧结果。

## 1. 可以进入下一步，但要区分通过的层次

FP32 的九点信号采集已完成，说明这条采集链可运行；两个正确短答案均来自 case 8 的较晚位置。它仍不能证明“摘要后继续”有益，因为本轮没有执行这一动作。九个位置只有三道已探索开发题，不是九个独立任务，更不是封存测试集。

下一步最有信息量的工作是对**相同九个前缀**获得动作结果，回答：此处立即摘要／重置，与继续原生推理相比，是否降低成本或改善答案？单纯继续增加 H/C 散点，不能回答这个问题。

## 2. 在同一轮加入两项小规模补检

### 2.1 补齐另外两题的长前缀一致性检查

当前 chunk128/64 的 H 与实际 C 比较只覆盖 case 1 / cut 4103。case 6 / cut 4203 的实际输入更长，case 8 / cut 4173 又含本轮唯一正确答案类型。建议对这两个预先指定点补做相同的两种窗口与两种 chunk 的真实 probe 对比，保留现有工程阈值。若失败，先定位受影响测量，不扩展干预。

这不是要求每次重复全部九点，也不能保证其他位置绝对无误；它以很少的新增重放覆盖每道题的最长前缀。新结果写入独立补检目录，旧九点数据不回写。

### 2.2 修正负号内容置信度的解释，记录权重指纹

case 8 的 `{-` 是一个 token，当前严格内容诊断将它作为混合格式 token 排除，因而 `strict_content_C` 仅覆盖答案 `-1` 的 50% 字符。后续不得将约 0.999 的该列解释成完整答案（尤其负号）的置信度。无需重跑模型：保留主 C 与所有 token 概率，再补充“与答案内容有交集的 token 概率均值”诊断列，明确其仍含混合 token 的格式概率；同时始终显示字符覆盖率。不能把一个 token 的概率任意拆成负号与括号的两个概率。

在下次运行中记录完整 `model.safetensors` SHA256，配合现有 config/tokenizer/代码/前缀指纹。当地文件指纹能固定跨轮身份，但独立证明 Hugging Face revision 仍需可信下载清单或该 revision 的权重哈希；它也不能独自确定 cold-start、task-RL、T+E 的主表行。

## 3. 首轮动作实验：同九点，18 条 A/B 轨迹

建议先固定如下协议，再运行；不要看分支结果后改变预算、摘要失败处理或采样次数。

|项目|首轮设置|原因|
|---|---|---|
|前缀|沿用当前九点及其精确 token ID SHA256|筛选不再依据答案是否正确或信号值|
|checkpoint / 数值|同一固定权重、FP32、关闭 TF32、固定后端|先避免信号与动作来自不同精度的额外混杂|
|A：继续|从精确保存前缀继续；允许模型之后自然摘要|对应既有模型原生机制，并非“禁止所有摘要”|
|B：摘要后继续|同一前缀插入一次已审计的摘要控制后缀；同一模型生成摘要，再以原题＋最新摘要重建上下文；之后与 A 同样允许自然摘要|唯一外部干预是当前位置强制一次摘要／重置|
|短答案选择 C|复用本轮同前缀、同精度的贪心 probe 答案与完整概率记录|不将既有 C 重复运行成额外独立样本；若未来定义是 `</think>` 后生成最终答案，则必须另外测该不同动作|
|A/B 解码|temperature=0.7，top_p=0.95；第一轮基础 seed=2026|与既有采样探索保持可解释关系；第一轮只做动作与运行检查|
|数量|9 前缀 × 2 动作 × 1 seed = **18 条轨迹**|先检验动作、预算与记录链，再投入重复采样|
|首个检查对|预先固定 case 1 / cut 4103 的 A/B；运行和预算检查通过后完成余下 16 条|不按结果挑选“有希望”的位置|
|第二批（第一批工程通过后）|所有九点补 seed=2027、2028，共36条；合计54条 A/B轨迹|不能只给首轮赢家补种子；三seed仍只是探索性证据|

首批 18 条的最坏追加生成上限为 **251,092 token**，三 seed 合计上限 753,276 token；因此“18 条”不等于瞬时完成。先用首个预定 A/B 对实测生成速度与实际消耗，再判断算力预算，避免承诺未经测量的完成时间。共享前缀复用保存 IDs，不重新生成；上限中的 cut 是公平预算核算，不是再次执行的生成开销。

“相同基础 seed”是配对设计，不保证不同输入／不同调用次数使用相同随机轨迹。应保存每次请求实际 seed，并用显式的 case、cut、replicate、调用序号映射；避免同题不同 cut 无意共用或覆盖记录。不同调用角色也要可追溯，不把 B 的摘要调用悄悄改变成 A 的同一随机样本。

本阶段无需先把所有测量迁回 BF16。等 FP32 下动作本身与信号是否有信息较清楚后，再进行 BF16／优化后端的桥接与实际总成本实验。**在这项桥接完成前，不宣称方法已适配 BF16 部署或复现论文 BF16 速度。** FP32 与 BF16 的 H 差异并非严格为零，不能混在一列里计算规则或阈值。

## 4. 公平预算必须重做，不能直接复用旧分支运行器

建议保留易与历史预算对应的全程生成上限 `B_total=16384`，包含该题已保存的共享生成前缀 `cut`。当前动作的剩余预算：

```text
R(case, cut) = 16384 - cut
```

同一前缀的 A、B 使用完全相同 R。所有模型生成 token——推理、强制摘要、原生摘要、最后答案、失败摘要——都从 R 扣除。外部插入的控制 token 不冒充模型生成 token，但作为输入 token 和 prefill 成本单独计入。原题输入不计入“生成 token”预算，却必须计入输入计算成本。

B 的一次强制摘要最大生成 1024 token（并受 R 约束），到合法闭合摘要标签提前停止。成功后仅使用原题＋最新摘要＋合法 think 前缀重建输入，核验旧详细推理确实移除，摘要没有被截断、重复 BOS 或遗漏。A/B 后续自然摘要使用同一解析与重置函数。

必须修复旧运行器已知的两种不对称：

1. 旧 A 首次最多生成 `8192-cut`，一旦调用因 length 结束就直接返回，尽管总体 R 仍有余额。新协议中，调用块长度是工程调度参数；只要未生成最终答案／有效摘要且预算仍有余额，就保留相同上下文（或 KV）继续生成，不能把 API 块结束当整个动作失败。
2. 旧 B 强制摘要占用“三个 segment”之一，从而额外减少后续推理轮数。新协议不用这一不对称调用次数限制；停止条件以共同生成预算、有效最终结束和明确定义的运行异常为准。若设置额外安全上限，A/B 同样适用、写入配置，并把触发单列，不能悄悄计作常规答错。

这样允许一段无摘要推理跨过工程调用块，它是本项目的内部公平预算协议，不等同论文每轮 8k 的完整主评测。后续若要正式复制论文上限，需作为独立协议报告。

建议明确 B 摘要失败的预设处理：在 1024 上限内未得到合法非空摘要时，**记录失败，保留已花费 token／时间，回退到原始前缀继续，R 扣除失败摘要开销**；不免费重试，不凭参考答案决定回退。不发生重置的失败尝试仍属于 B 分配组，按 intention-to-treat 统计，同时单列实际成功 reset 的诊断结果。若选择“失败即终止”也可作为另一个协议，但不可结果出来后切换或丢弃失败样本。

自然生成遇到未闭合摘要、长度块截断、EOS 却无有效最终答案等必须区分。长度块边界若还有预算应继续；EOS 或总预算耗尽仍无有效结果则记 incomplete。系统 OOM、进程中断属于执行失败，不自动当作模型答案错误；恢复后从完整记录定位，不覆盖旧轨迹。

## 5. 每个前缀需要得到的动作标签与成本

分别记录而不强行合并成单一“有益”分数：

- 结果：A/B 是否完成、最终答案是否正确、摘要是否生成和成功重置、失败／截断类型。
- 成本：共享前缀 cut，追加生成 token，所有摘要 token，输入与重建 prefill token，GPU 同步后的分支耗时，峰值显存，调用与重置次数。
- 动作差异：`correct(B)-correct(A)`；两者都正确时再比较追加 token、实测时间；同样错误不能凭更短宣布得到高质量效率收益。
- 答案就绪：本轮 C 是否正确，及其概率范围、格式混合情况。它与 `B 相对 A 的收益` 是两种标签。

监测 H/C 的代价须另存。当前采集使用独立重放 prefill，尚未集成到在线推理；将旧重放时间加上新分支时间，只能算离线成本账，不能称真实在线时延。最终控制器相对原生 A 的效率比较，需要在同一硬件／dtype／后端中真实计入监测、probe、摘要生成、重置 prefill 及所有被试探但未采用的计算。原生基线没有外部监测成本，不能人为给它加上相同开销以制造公平。

FP32 本阶段定位动作与信号信息，不以比 BF16 历史轨迹快慢作为结论。最终还需明确 prefix caching、模型暖机、执行顺序与计时边界。

## 6. 从本阶段得到什么后再扩展

三seed、三题仍不能估计泛化准确率或宣称联合规则显著优越。它只用于核对：是否存在稳定的摘要效用差异、C 是否更多表示答案已就绪、H 的变化是否只是长度归一化，以及同题不同位置的信息是否可能支持选时机。

若存在可复查的动作差异，下一批按预先固定的无标签规则扩展开发题（例如同一选点计划剩余合格题），不以已知正确性挑题。再考虑固定／随机／长度、H-only、C-only、联合规则、原生机制与直接早停等对照。阈值选择与评价分离，封存 test120，不训练新权重。

若某些摘要普遍失败，先查解析、提示与 checkpoint 摘要能力；若所有预算都截断，先诊断预算覆盖，不能将执行截断等同 idea 失败。若在充分核对动作有效、预算对称与多题控制后，联合信号持续不优于长度／单信号，再据证据讨论该特定方法是否值得继续。

无论下一批结果如何，都不以旧固定时机 A/B 结果或本轮 2/9 的短答案正确数单独宣布原始联合信号方向成功或失败。
