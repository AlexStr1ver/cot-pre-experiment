## 真实 GPU canary 的结果

实际双 chunk 检查只在 case 1 / cut 4103 进行，输入 4158 token；chunk128 与 chunk64 对比如下：

|检查|raw tail32|ASAG-style 12 query|
|---|---:|---:|
|H 相对差|1.5869×10^-8|4.5383×10^-8|
|logit 平均绝对差|2.5250×10^-6|1.3290×10^-6|
|logit 最大绝对差|1.5259×10^-5|7.1526×10^-6|
|下一 token 一致|是|是|

真实答案 probe 也执行了两种 chunk 的完整贪心生成：token IDs 与状态相同；逐 token 概率最大差 `6.5565×10^-7`，C 差 `1.5895×10^-7`。这补上了仅用 attention replay 的最终 logits 推断答案 probe 稳定性的不充分之处。

H≤1%、平均 logit 差≤0.05、probe 逐 token 概率差≤0.01 的原定工程门槛均通过，未靠放宽阈值。全部 18 个主窗口的 attention 行概率质量最大偏差仅 `3.5763×10^-7`，符合 FP32 量级。

与旧 BF16 的 raw-tail logit 均差 0.119981 相比，本次同一前缀/同一 GPU 型号的差异明显减小，**支持旧停止与低精度数值计算路径相关的解释**。仍未逐个 kernel 定位机制，也没有完成 BF16 与 FP32 的输出等价性验证；不能把本轮 FP32 成功写成 BF16 问题已经在相同数值设置下修复。

## 未覆盖项目与建议优先级

### 下一轮小实验宜补，但不撤销本轮通过

1. **真实模型双 chunk 检查只覆盖一个题目的一个位置。** 实际最长输入是 case 6 / cut 4203，共 4358 token，长于 canary 的 4158；case 8 的后期输入也不同。现有各点显存均已实测正常，缺的是不同内容和早/晚阶段的数值对照。建议下一轮顺带对 case 6、case 8 的后期点及至少一个早期点加第二种 chunk；仅九点时也可全部双 chunk，总重放规模仍很小。它是扩大覆盖范围，不是为本轮错误补救。
2. **FP32 与原 BF16 推理口径尚未桥接。** 原 native20 前缀来自 BF16，当前读取同一离散前缀后用 FP32 测量。这在“固定前缀诊断”上合法，但正式方法若部署 BF16，就应对同前缀 H、C、答案、动作排序做精度敏感性检查。后续小规模配对动作可以先保持 FP32，一次只改变动作，避免精度变化混入动作效应；BF16 效率主张应等待相应验证。
3. **权重内容身份未独立验证。** 配置与 tokenizer 已核验，返回包只记录 `model.safetensors` 大小 3,554,214,720 bytes，未记录其内容 SHA256。固定 revision 到 cold-start/task-RL/T+E 的主表行映射也仍缺发布证据。下一次运行可一次性记录权重 hash，再与固定 revision 的可信下载记录核对。暂将结论限定为本地固定 checkpoint，勿猜训练阶段。

### 正式论文或在线效果实验需要，当前阶段尚未开展

- **不存在真实长序列 full-attention GPU reference。** 当前只有同一个实现的不同 chunk 交叉比较，另有 CPU tiny-Qwen2 full/chunk 测试。不能排除共同实现偏差；不用为了这一点默认保留所有层 4k 全 attention 张量而引入显存风险。可按需要做真实模型短序列 full reference 和有限窗口的额外对照。
- **没有保存完整 logits／attention 矩阵，也未重复独立进程运行。** 返回包中的 logits 诊断由运行时函数计算，离线只能验证记录的指标与门槛关系。当前无异常，不必为了存下全部矩阵扩大实验；若出现路径差异，可选择性保留可复核的向量或摘要。
- **没有测试摘要／重置的动作价值。** 这里全部是离线 H+C 采集，没有 continue/summary-reset/answer 的预算对称反事实比较，没有规则选择评估、种子重复或端到端监测成本对照。
- **答案置信度的语义未被这些工程测试证明。** C 按既定定义包含生成的括号等格式 token，内容均值另存。测试能证明算式、停止位置及数值一致性，不能证明 C 是正确率校准概率，或能判断“适合摘要”。
- 当前采用段落计划点，ΔH 相对同题最早选点，并非 ASAG 首次 ATP；本轮仍非完整 ASAG 的 ATP、早停、概率注入和 jump prompt 复现。

没有发现需要作废这九点的工程缺陷。合理下一步是保存本轮作为 FP32 信号测量基线，携带少量上述数值覆盖检查进入同前缀的动作配对验证，而不是直接扩大样本、调到理想阈值或改为训练判别器。
